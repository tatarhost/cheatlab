# AIL AI — архитектура и план обучения

AIL AI — отдельная модель CHEATLAB для программирования и обычного общения. Целевая конфигурация: около 1 000 000 000 обучаемых параметров.

## Что уже есть в CHEATLAB

- Основной API и аккаунты работают через Cloudflare Worker.
- D1 хранит данные аккаунтов и приложения.
- В `worker/wrangler.toml` уже объявлен binding `AI` для Cloudflare Workers AI.
- Worker может быть контрольным слоем: авторизация пользователей, API-ключи, лимиты, метаданные запусков, статусы и проксирование запросов к отдельному вычислительному серверу.

## Важное ограничение инфраструктуры

Cloudflare Workers AI предоставляет инференс готовых моделей и поддержку инференса собственных моделей/LoRA, но не предоставляет GPU-машины для обучения модели с нуля. Обычный Worker также не подходит для непрерывного обучения модели на 1B параметров.

Поэтому нельзя честно запустить круглосуточное обучение AIL AI на одном только текущем Worker. Для настоящего обучения нужен отдельный постоянно работающий GPU compute server, доступный через приватный HTTPS API. CHEATLAB Worker должен управлять задачами и проверять права, а не выполнять обучение внутри коротких Worker-запросов.

До подключения такого GPU-сервера нельзя показывать фиктивный прогресс или заявлять, что модель уже обучается.

## Данные-кандидаты

### Код
- The Stack v2: https://huggingface.co/datasets/bigcode/the-stack-v2
- Коллекция содержит код из сотен языков, но bulk-доступ требует согласования с Software Heritage и INRIA. Лицензии исходных репозиториев различаются; нужно сохранять происхождение и соблюдать условия исходной лицензии.
- Начинать с разрешённой и проверенной подвыборки, а не скачивать весь архив.

### Обычный и многоязычный текст
- FineWeb2: https://huggingface.co/datasets/HuggingFaceFW/fineweb-2
- ODC-By 1.0; набор собран из Common Crawl, поэтому необходимо учитывать условия Common Crawl и требования атрибуции.
- Отбирать русский и английский языки, очищать дубликаты, навигационный мусор, персональные данные и секреты.

## Начальная смесь данных

Гипотеза для первых экспериментов, которую нужно корректировать по результатам тестов:
- 45% код с проверенными правами и лицензиями;
- 30% обычные тексты на русском и английском;
- 15% техническая документация и объяснения;
- 10% качественные пары «инструкция — ответ» и примеры исправления кода.

Создать отдельные train/validation/test наборы по репозиториям и источникам, чтобы близкие фрагменты не попадали одновременно в обучение и тестирование. Не обучаться на закрытых репозиториях, секретах, ключах и данных пользователей CHEATLAB без отдельного согласия.

## План модели и обучения

1. Заменить экспериментальную byte-level модель NEXUS на архитектуру decoder-only Transformer с BPE/SentencePiece токенизатором.
2. Зафиксировать конфигурацию около 1B параметров и автоматически проверять фактическое число параметров перед запуском.
3. Реализовать устойчивые checkpoint/resume, периодическую валидацию, логирование loss, learning rate, throughput, GPU memory и ETA.
4. Запускать периодические smoke-тесты генерации на отдельном тестовом наборе, а после этапов — тесты программирования и обычного текста. Тесты не должны подмешиваться в обучающие данные.
5. Сохранять checkpoints и логи на постоянном хранилище вычислительного сервера; в D1 хранить только метаданные запусков и агрегированные метрики.
6. Публиковать ZIP весов только после проверки целостности, конфигурации, tokenizer и тестового отчёта.

## CHEATLAB API и права

- Вход в AI Lab — через существующую сессию CHEATLAB.
- API-ключи создавать и отзывать только на сервере; хранить только хэш ключа.
- Бесплатный доступ к ключу — 10 дней с даты выдачи, затем автоматическое истечение.
- Администратор определяется исключительно по серверной роли/ID аккаунта, никогда по нику, переданному браузером.
- Администраторский доступ без лимита должен проверяться на каждом запросе сервером.
- Ник `spinogrz666` сам по себе не является подтверждением личности или внутреннего user ID; назначение роли требует найти точную запись аккаунта в D1 и выполнить защищённую административную операцию.
- Нельзя встраивать секреты compute-сервера или мастер API-ключ в frontend, GitHub или публичный репозиторий.

## Что требуется для реального старта

1. Доступный GPU compute server с постоянным диском и достаточной памятью для выбранной стратегии обучения 1B.
2. Приватный HTTPS endpoint сервера для запуска/остановки задач, чтения логов/метрик, тестирования и скачивания checkpoint.
3. Секреты подключения, добавленные владельцем в Cloudflare Worker secrets, не в исходный код.
4. Проверка реального аккаунта `spinogrz666` через существующую административную панель CHEATLAB перед выдачей админ-прав.

Пока пункты 1–3 не выполнены, CHEATLAB может показывать только честный статус «сервер обучения не подключён», а не имитировать обучение.
